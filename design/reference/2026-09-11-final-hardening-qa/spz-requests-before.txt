ROOT CAUSE (corrects the earlier handoff note)
  The aborted request is the HEAD, not a second GET, and the scene effect runs exactly once per
  load: only one HEAD and one GET are ever issued. `useFlyControls()` already returned
  useCallback(fn, []), so the `connectControls` entry in the effect's dependency array was stable
  and never caused a teardown/restart.
  The HEAD existed only to read Content-Length for the progress bar. Its response body stream is
  never consumed, so Chrome cancels the request as soon as the following GET starts and logs
  net::ERR_ABORTED against it.

The HEAD carried no information the GET response does not already carry:
  local production build:          HEAD 200 Content-Length 4303196  |  GET 200 Content-Length 4303196
  live, Accept-Encoding: br:       HEAD 200 no content-length       |  GET 200 no content-length
  live, Accept-Encoding: identity: HEAD 200 Content-Length 4303196  |  GET 200 Content-Length 4303196
  On the live site (brotli) the HEAD never yielded a length at all, so the bar was already
  indeterminate there and the extra round trip bought nothing.
